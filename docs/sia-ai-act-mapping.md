# SIA Sentinel ↔ EU AI Act: карта соответствия

**Дата:** 2026-09-13 · **Статус:** рабочий документ для разговоров о спросе
(банки, госзакупки, грантодатели). Не юридическая консультация.

## Зачем этот документ

EU AI Act с 2 августа 2026 применяет запрещающие практики, с 2 августа 2027 —
системы по приложению III (high-risk), с 2 августа 2028 — встроенные в
регулируемые продукты. Обязательства high-risk-систем (Еврокомиссия,
digital-strategy.ec.europa.eu): оценка и снижение рисков, качество датасетов,
**логирование для трассируемости результатов**, **техническая документация
для надзорных органов**, информация развёртывающей стороне, человеческий
надзор, кибербезопасность и точность. Еврокомиссия строит third-party
assessment capacity к 2027.

Каждая аттестация SIA структурно производит артефакты, которые этот
регуляторный список называет. Таблица ниже — карта «требование → поле
аттестации sia-attestation/1», для питча организациям, живущим под
AI Act / модельным риском / госзакупками.

## Карта

| Требование AI Act (high-risk) | Артефакт SIA | Где живёт |
|---|---|---|
| Логирование для трассируемости (logging of activity) | Хеш-цепь TrustChain: каждая запись `seq → prev_hash → entry_hash`, удаление/вставка/перестановка ломают цепь; подписанные чекпойнты фиксируют голову + Merkle-корень (RFC 6962) | `receipts/registry.jsonl`, `receipts/checkpoints.jsonl` |
| Техническая документация для надзора | Аттестация `sia-attestation/1`: переносимый документ с манифестом (датасет-хеш, конфиги обеих сторон, повторения), парной статистикой, вердиктом, подписью Ed25519 | `GET /v1/attestations/{id}` |
| Оценка рисков / качество модели до развёртывания | Предрегистрация `sia-preregistration/4`: δ, n, метрика, конфиги и цены фиксируются в цепи ДО прогона — «ворота нельзя переставить после результата» | seq=1 леджера, поле `claim.preregistration` |
| Точность (accuracy) | Тест неинфериорности: MOVER-интервал на дискордантных парах, точный Макнемар, ворота MDD («прогон мог бы заметить падение на δ или честно говорит: недостаточно данных — inconclusive») | `claim.paired` |
| Качество датасетов | `dataset_sha256` прошит в манифест, квитанцию и предрегистрацию; воспроизводимость — `replay_tolerance` задекларирован до прогона | `manifest.dataset_sha256`, шаг 1 `sia-rederive` |
| Надзор может проверить сам, не доверяя оператору | `pip install sia-verifier`: подпись, цепь, чекпойнты, Merkle, перевывод вердикта из первичных чисел, живой Rekor-якорь + RFC 6962 inclusion-proof — без аккаунта, без доверия SIA | PyPI `sia-verifier` ≥1.3.1 |
| Внешний свидетель целостности истории | Якорь обязательства в публичном логе Sigstore Rekor (запись №1: `rekor:108e…f00c8:2601942504`) | `flows/beacon.json`, шаг 2-9 `sia-rederive` |
| Информация развёртывающей стороне | Человекочитаемый портал вердикта (ru/kk/en) + embed-бейдж с экономией и вердиктом | `/attestations/{id}?lang=` |

## Что НЕ покрыто (честные границы)

SIA не покрывает: человеческий надзор (статья про oversight), защищённость
данных при обучении, prohibited practices, FLOP-пороги GPAI. SIA — не
«сертификат соответствия AI Act», а **протокол доказуемой верификации
заявлений об ИИ**, закрывающий трассируемость/документацию/точность
машинно-проверяемым артефактом. Эта узость — фича: контролируемые
обязательства мы выполняем криптографически, а не обещанием.

## Ключ для переговоров

1. **Банки (SR 11-7 / Нацбанк РК модельный риск):** «независимая валидация и
   эффективный вызов» — пере-вывод вердикта третьей стороной из
   опубликованных артефактов это валидация в чистом виде; квитанция —
   повторяемый артефакт для надзорной экспертизы.
2. **Госзакупки ИИ:** требование «поставщик прикладывает аттестацию,
   которую закупщик проверяет сам» — SIA даёт обе стороны одной командой
   (`pip install sia-verifier`), бюджет проверки — нулевой.
3. **EU-facing поставщики из КЗ:** соответствие трёх высоких требований
   AI Act (логирование/документация/точность) машинно-проверяемо —
   снижает цену выхода на рынок ЕС.
